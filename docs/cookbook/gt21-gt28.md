# GeoTask GT21–GT28 World-State Cycle Cookbook

This cookbook covers the path from structured Observations into an explicit World State, followed by state change, impact propagation, bounded correction, incremental reevaluation, and action gating. Every example uses fictional data and keeps structural validity, exact binding, external truth, and action authorization separate.

## GT21: Can arrival order decide which Observation overwrites a state value?

The base World State records `uav-b.delay_seconds = 40`. Two fictional Observations then claim 60 and 55 seconds, and the caller maps both claims to:

```text
/objects/uav-b/attributes/delay_seconds
```

Without a target-scoped policy, the merge fails closed with `conflict_policies: duplicates target path without explicit conflict policy`. Core must not apply last-arrival-wins, average unequal values, misuse `require_equal`, or infer which source is authoritative.

The caller supplies a complete `explicit_precedence` order. Core mechanically selects its first application as `applied`, records the other as `superseded`, emits World State revision 2 with a value of 55, and leaves `next_action=compute_state_transition`. This does not establish external truth, source authority, completed impact propagation, output release, or action authorization.

Run the executable case:

```bash
python -m pytest tests/test_gt21_observation_conflict_case.py -q
```

## GT22: How do two Observations become the first referenceable World State?

Two fictional sensor Observations claim a local ENU position of `(120, 80, 35)` metres and a battery level of 68% for `uav-alpha`. The caller supplies an explicit `object_plan` that names the object, its type, and the target attribute for every claim.

The case-specific builder strictly loads both Observations, requires every claim to be mapped exactly once, fixes the initial snapshot at revision 1, requires `as_of` to equal the latest Observation time, and validates the generated payload through the public World State v0.1 loader and JSON Schema. Reversing the Observation file order produces the same normalized snapshot and semantic fingerprint:

```text
bb57804b830e08dc361bc04e3ca96f4530ea525c198857492dcb6c304dbe540f
```

A reference-closed World State still does not bind the exact source-file bytes. Adding insignificant whitespace to an Observation file leaves its loaded semantics and the World State fingerprint unchanged. Exact byte binding must be established by a later Artifact such as a Verification Session. The snapshot remains `asserted`; it does not establish external truth, compute a State Transition, or authorize action.

Run the executable case:

```bash
python -m pytest tests/test_gt22_initial_world_state_case.py -q
```

Builder example: `examples/core/gt22_build_initial_world_state.py`.

Experience page: `site/gt22/index.html`.
