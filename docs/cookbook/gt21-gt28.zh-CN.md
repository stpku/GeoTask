# GeoTask GT21—GT28 世界状态循环案例手册

本手册覆盖GeoTask从多源运行数据进入统一状态，到状态变化、影响传播、限定纠偏、增量复核和行动门控的案例。GT21之后统一采用“现实场景优先、必要性先行、技术概念后置”的叙事：主标题先说明用户正在处理的任务和可能犯的错误，World State、State Transition等术语只在技术实现部分解释。每个案例都使用虚构数据，并区分结构有效、精确绑定、外部真实和行动授权。

## 案例叙事规则

每个案例页面必须依次回答：现实中发生了什么、为什么必须解决、普通AI容易犯什么错误、GeoTask如何验证、用户最终得到什么，以及仍然不能证明什么。Artifact、revision、semantic fingerprint、materialization等术语不得替代现实问题成为主标题。

## GT21：遥测显示延误60秒，运行审核记录显示55秒，AI应该相信哪一个？

### 场景

基准World State中的`uav-b.delay_seconds`为40秒。随后收到两条虚构Observation：

- 遥测Observation声明延误60秒；
- 运行审核系统Observation声明延误55秒。

两条命题都被调用方显式映射到：

```text
/objects/uav-b/attributes/delay_seconds
```

### 错误做法

- 按文件或消息到达顺序选择最后一条；
- 将60秒与55秒求平均；
- 把不同语义的命题交给`require_equal`；
- 让Core自行判断哪个来源更权威。

这些做法都会引入未声明的排序、推断或数值规则。

### 正确做法

没有目标级冲突策略时，Observation Merge失败关闭：

```text
conflict_policies: duplicates target path without explicit conflict policy
```

调用方随后提供完整策略：

```python
ObservationMergeConflictPolicy(
    target_path="/objects/uav-b/attributes/delay_seconds",
    strategy="explicit_precedence",
    precedence=(
        "obs-uav-b-delay-ops-review#uav-b-delay-seconds",
        "obs-uav-b-delay-002#uav-b-delay-seconds",
    ),
)
```

Core只机械执行这份完整顺序：

- 审核记录application：`applied`；
- 遥测application：`superseded`；
- 后继World State：revision 2；
- `delay_seconds`：55秒；
- `next_action`：`compute_state_transition`。

### 安全边界

该结果不证明审核记录真实、权威或经过独立核验，也不代表State Transition已经计算、影响已经传播、输出已经释放或行动已经授权。真实优先级规则必须由调用方、Runtime或Domain Pack明确提供。

### 运行测试

```bash

```

## GT22：无人机的位置和电量来自两个系统，AI怎样形成同一时刻的可靠运行快照？

### 场景

两条虚构传感器Observation分别声明：

- `uav-alpha`在本地ENU坐标系中的位置为`(120, 80, 35)`米；
- `uav-alpha`电量为68%。

Observation只表达带来源、时间和不确定性的命题。调用方必须另外提供显式`object_plan`，声明对象ID、对象类型以及每个claim进入哪个属性。

### 构造门禁

GT22案例构造器要求：

- 每个Observation先通过严格加载；
- 首个快照固定为revision 1；
- `as_of`等于最新Observation时间；
- 每个claim恰好映射一次；
- claim的`subject_ref`必须等于调用方声明的对象ID；
- 不支持未声明对象、重复属性或关系claim；
- 生成结果再次通过World State v0.1严格加载和JSON Schema验证。

固定结果包含一个`uav-alpha`对象、两个属性、两条Observation引用和两条Evidence引用，语义指纹为：

```text
bb57804b830e08dc361bc04e3ca96f4530ea525c198857492dcb6c304dbe540f
```

### 关键边界

World State的引用闭包不等于Observation原始文件字节绑定。只改变Observation JSON的空白字符，严格加载后的语义和World State指纹仍可保持不变。精确文件绑定需要由Verification Session等后续制品明确完成。

该快照的可信状态仍为`asserted`；它不证明外部真实，不计算State Transition，也不授权行动。

```bash

```

## GT23：无人机飞行五分钟后位置和电量都变了，系统如何证明“现在”不是“刚才”？

### 场景与必要性

10:02时，`uav-alpha`位于本地ENU坐标`(120, 80, 35)`米，电量68%；300秒后的10:07，位置变为`(260, 180, 48)`米，电量降至52%。如果系统只覆盖最新字段，历史状态、变化幅度和变化依据都会丢失，后续航线冲突、电量余度和返航判断也无法复核。

GT23保留revision 1，构建revision 2，并明确记录：

- 位置从`(120, 80, 35)`变为`(260, 180, 48)`；
- 电量从68%变为52%；
- 对象有效期从10:02:30刷新至10:07:30。

有效期刷新是必要的：GT22对象原有效期早于10:07，不能为了生成后继快照而静默延长。

### 构造与绑定

案例构造器严格加载两条新Observation，要求每个claim恰好映射一次，并生成后继World State。随后构造State Transition，绑定同一`world_state_id`下的revision 1与revision 2、各自`as_of`和语义指纹，并逐项检查声明的before/after值确实等于两个快照中的值。

固定后继快照指纹：

```text
4a5112aa71e7286ef37c69ef25af961e15894b25cbe5b7f948dbc4d3b81e1419
```

固定State Transition指纹：

```text
bc12e7c9332e824f27386a43eeae137e493b759fe7dea20b5383539dfaf313e7
```

### 关键边界

公共State Transition v0.1加载器验证结构、时间顺序、引用闭包和快照指纹绑定，但本身不执行通用diff，也不证明所有变化已经自动发现。GT23构造器仅对本案例显式声明的3条路径执行额外核验。

该结果不传播影响，不重算风险，不验证外部真实，也不授权飞行、返航或其他行动。下一步是评估哪些任务和结论受到变化影响。

### 运行测试

## GT24：临时禁飞区发布后，哪些航线、任务和审批结论必须重新检查？

### 场景与必要性

一处虚构临时禁飞区在14:00—16:00生效。医疗航线A计划于14:30—14:50飞行，调用方声明其与禁飞区相交；巡检航线B计划于14:35—14:55飞行，调用方声明其从区域南侧绕开。

系统不能采用两个极端做法：

- 不能把所有航线、任务和审批全部重算，否则会无依据扩大业务影响；
- 不能只更新地图后继续沿用旧任务放行和审批结论，否则下游决策会与当前空域状态脱节。

GT24将影响范围限定为：

- 医疗航线A的空域避让断言；
- 医疗任务17的放行断言和调度输出；
- 医疗审批17的放行结论；
- 医疗任务17的起飞动作。

巡检航线B、巡检任务08及其审批不进入该影响图。

### 构造与绑定

案例将虚构禁飞通知加载为Observation，将当前航线、任务和审批清单加载为World State revision 2，再生成一份Discrepancy Report，记录旧医疗任务放行结论已经过时。Impact Graph以该差异为根，连接7个节点、7条边和4个复核目标，阻断2个输出和1个起飞动作。

固定World State指纹：

```text
819d68c21176a6d0f5b78946b37ed80a7c7d31074b30c823fc0ddded6af348f0
```

固定Discrepancy Report指纹：

```text
250aa032c3908dff58f1bad5e85c5eba36cc195fa76d4ff6e40ba0bd34fd1512
```

固定Impact Graph指纹：

```text
12e7908066d35dc9d7cbe161996b7d22aaddeec32b0cb6013eddf5c1a83a2a2e
```

构造器验证World State、Observation、Discrepancy Report和Impact Graph的严格格式、精确字节绑定、无环结构、声明影响集合和不受影响集合。若遗漏一个受影响节点、把巡检航线错误标记为相交，或篡改被绑定的差异报告字节，案例均失败关闭。

### 关键边界

本案例使用调用方已经声明的航线—禁飞区相交关系，不由Core重新执行几何求交。Impact Graph只验证一份显式、有限的依赖声明，不自动发现所有潜在影响，也不证明未进入图的对象在现实中绝对不受影响。

该结果不执行影响传播，不重新运行航线或任务检查，不发布新放行结论，不验证外部通知真实性，也不授权起飞。
