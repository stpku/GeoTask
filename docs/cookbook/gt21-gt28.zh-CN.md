## GT21：两条观测同时更新同一状态，系统能按到达顺序覆盖吗？

### 场景

基准World State中的`uav-b.delay_seconds`为40秒。随后收到两条虚构Observation：

- 遥测Observation声明延误60秒；
- 运行审核系统Observation声明延误55秒。

两条命题都被调用方显式映射到：

```text
/objects/uav-b/attributes/delay_seconds
```

### 错误做法

- 按文件或消息到达顺序选择最后一条；
- 将60秒与55秒求平均；
- 把不同语义的命题交给`require_equal`；
- 让Core自行判断哪个来源更权威。

这些做法都会引入未声明的排序、推断或数值规则。

### 正确做法

没有目标级冲突策略时，Observation Merge失败关闭：

```text
conflict_policies: duplicates target path without explicit conflict policy
```

调用方随后提供完整策略：

```python
ObservationMergeConflictPolicy(
    target_path="/objects/uav-b/attributes/delay_seconds",
    strategy="explicit_precedence",
    precedence=(
        "obs-uav-b-delay-ops-review#uav-b-delay-seconds",
        "obs-uav-b-delay-002#uav-b-delay-seconds",
    ),
)
```

Core只机械执行这份完整顺序：

- 审核记录application：`applied`；
- 遥测application：`superseded`；
- 后继World State：revision 2；
- `delay_seconds`：55秒；
- `next_action`：`compute_state_transition`。

### 安全边界

该结果不证明审核记录真实、权威或经过独立核验，也不代表State Transition已经计算、影响已经传播、输出已经释放或行动已经授权。真实优先级规则必须由调用方、Runtime或Domain Pack明确提供。
