# GeoTask内部开源—闭源与低空商业化策略

> **内部资料，不得进入GitHub、公开主页、公共发布包或对外演示材料。**
>
> 本文件允许随GeoTask源代码同步至Gitee私有仓库，作为内部设计与备份资料。

## 一、仓库与发布边界

1. **Gitee私有仓库是完整源仓和内部备份仓。** 可保存公共Core源码、内部架构设计、商业化策略、专利敏感边界和低空行业协同方案。
2. **GitHub公开仓库是生态仓。** 只包含开放协议、公共SDK、开发者工具、通用参考实现、虚构案例、双语文档和生态建设资料。
3. GitHub不直接镜像Gitee，通过公共发布清单生成受控导出；任何未列入公开清单或明确标记为内部的目录都不得进入GitHub。
4. 项目公开主页聚焦“可验证时空世界模型、开发者采用、标准协议和生态案例”，不公开收费策略、客户策略、真实行业规则和闭源产品实现。

## 二、总体原则

1. GeoTask Core承担开放协议、稳定制品合同、确定性校验和失败关闭语义，作为开发者采用入口与生态基础。
2. Verification Provider公共层只开放接口、离线参考实现、模拟Provider和安全边界；真实权威数据连接、凭据、来源治理、质量评分、跨Provider仲裁和生产审计留在闭源运行时。
3. 低空行业能力包不公开真实监管规则库、阈值、评分权重、证据治理策略、数据源适配、客户流程和报告模板。
4. 低空选址平台不是GeoTask的替代产品，而是首个商业应用平台；GeoTask作为其可信任务协议、证据与状态闭环底座。
5. 公开案例只证明通用方法和安全边界，不公开真实客户数据、真实监管口径、专利敏感算法或可直接复刻商业产品的完整工作流。

## 三、产品分层

### 1. 开源层：GeoTask Core

公开内容：

- 机器可读协议与JSON Schema；
- 观测记录、世界状态、状态转换、验证会话等通用制品；
- 验证提供方描述符、验证请求、验证响应和可信保证档案公共合同；
- 失败关闭校验、精确绑定、确定性参考算子；
- 虚构案例、模拟Provider和开发者工具。

不承载：

- 真实数据凭据；
- 生产连接器；
- 真实监管规则；
- 商业评分模型；
- 自动审批与设备控制；
- 多租户、计费和运营能力。

### 2. 闭源层：GeoTask Runtime

闭源能力：

- 模型路由、成本与Token治理；
- Provider注册、凭据、调用编排、超时与重试；
- Provider可信度、独立性、校准和冲突仲裁；
- 数据连接器、证据湖、版本治理与审计；
- 任务生命周期、人工复核、权限与多租户；
- 生产输出发布、行动授权对接和可观测性。

### 3. 闭源行业层：低空行业能力包

闭源能力：

- 低空设施对象模型和规则本体；
- 机场、空域、气象、障碍物、人口敏感区等真实数据适配；
- 选址评分、风险模型、证据等级和缺口治理；
- 设施类型差异化规则；
- 局方和企业工作流、审批门禁、报告模板和复核策略；
- 客户专属规则与部署配置。

## 四、与低空选址平台的有机协同

低空选址平台作为商业应用前台，GeoTask作为可信任务与世界状态底座：

1. **资源库**：平台管理候选设施、地图、公开来源和内部资料；GeoTask将关键对象、证据、状态和有效期结构化。
2. **评估模型**：平台执行行业评分；GeoTask记录评分依赖的命题、来源、版本、变化和不可核验项。
3. **AI增强**：平台进行互联网、地图和模型增强；GeoTask验证提供方层约束数据来源、时效、独立性和可复核性。
4. **复核闭环**：平台派发人工复核和单站更新；GeoTask生成差异报告、纠偏请求、影响图和增量复核记录。
5. **决策报告**：平台形成选址、安全与监管报告；GeoTask提供证据链、模型影响说明和版本可追溯性。
6. **监管服务**：面向局方提供资源底账、风险筛查、证据核验、变化监测和复核闭环，不把GeoTask直接包装成独立监管平台。

## 五、商业化路径

### 阶段A：平台内嵌

- GeoTask先作为低空选址平台内部可信底座使用；
- 不单独售卖Core；
- 商业价值体现在数据治理、模型可信、报告审计和任务闭环。

### 阶段B：行业能力包

- 将飞行服务站、起降点、物流节点、测试场、机巢等形成独立低空能力包；
- 按城市、设施类型、数据规模和复核量授权；
- 提供私有化部署与局方监管版。

### 阶段C：可信验证平台

- 面向其他时空行业提供运行时与行业能力包；
- 收费项包括部署许可、行业包、数据连接器、模型调用治理、审计与运维服务；
- Core保持MIT许可，形成标准入口和生态影响力。

## 六、必须避免的公开披露

- 真实低空选址评分权重与风险算法；
- 证据源优先级、可信度传播与冲突仲裁细节；
- 真实监管阈值和客户规则；
- 私有数据源名称、接口、凭据与覆盖范围；
- 运行时编排、成本优化、模型路由和治理实现；
- 与既有专利权利要求高度重合、尚未完成申请布局的实现细节。

## 七、近期内部决策

1. GT29公开实现仅包含Provider合同、虚构风速冲突和模拟Provider。
2. 真实气象Provider、低空规则和选址平台连接器不进入公共仓库。
3. 对外路线图只写“Provider生态与行业扩展”，不写收费模式、客户策略和低空平台产品组合。
4. 内部后续建立独立私有Runtime仓与低空行业能力包仓，公共Core只保留SDK合同。
5. 所有内部文件在提交前必须通过公共导出验证，确保GitHub导出中不存在`docs/internal/`路径或内容。
