# GeoTask验证提供方接口规范v0.1

## 状态

本规范定义只读验证提供方如何把外部确定性算子、规则引擎、权威数据服务、传感器、本地预测模型和人工复核系统接入GeoTask核心。

本规范只定义合同和校验，不获取外部真实数据、不调用提供方、不发布生产结果、不授权行动，也不执行副作用。

## 接口

- 接口标识：`geotask.verification-provider`
- 接口版本：`0.1`
- 公共制品：
  - `geotask.verification-provider-descriptor`
  - `geotask.verification-request`
  - `geotask.verification-response`
  - `geotask.assurance-profile`

## 提供方类型

- 确定性算子
- 规则引擎
- 权威数据提供方
- 传感器数据提供方
- 本地预测模型
- 人工复核

机器字段继续使用稳定英文标识：

```text
provider_type:
  deterministic_operator
  rule_engine
  authoritative_data_provider
  sensor_data_provider
  local_predictive_model
  human_review
```

验证提供方描述符声明一个提供方的身份、版本、类型、能力、支持方法、独立分组、可复现性、校准状态、有效期、审计能力和副作用边界。

提供方不能自行提升可信保证等级。描述符和响应只能陈述自身实现与结果，调用方编写的可信保证档案负责判断多个绑定结果是否满足数量、独立性、时效、可复现性、校准和冲突策略要求。

## 验证提供方描述符

描述符记录：

- 稳定身份和版本；
- 提供方类型与实现类型；
- 能力和验证方法；
- 独立分组；
- 可复现性和校准状态；
- 描述符有效期和审计支持；
- 凭据是否由外部管理；
- 明确的无副作用边界。

模拟提供方不能声明为生产就绪，公共提供方不能允许外部副作用。

## 验证请求

验证请求绑定：

- 一个明确命题及其有效期；
- 输入制品引用和精确SHA-256；
- 一个验证方法；
- 必需能力；
- 允许的提供方类型；
- 一份精确绑定的可信保证档案；
- 截止时间；
- 不允许副作用和不授权行动的标志。

GeoTask核心只判断描述符能否接受请求，不会向外部系统提交请求。

## 验证响应

验证响应绑定：

- 验证请求的精确字节；
- 提供方描述符的精确字节；
- 响应状态和有类型结果；
- 证据引用；
- 与描述符一致的独立分组、可复现性和校准状态；
- 诊断信息和完成时间。

以下字段必须保持为假：

```text
independently_verified
production_output_released
action_authorized
action_executed
```

响应中的可信保证声明必须与描述符完全一致。提供方不能在响应中发明新的独立分组，或自行提升校准与可复现性状态。

## 可信保证档案

调用方编写的可信保证档案声明：

- 最少提供方数量；
- 最少独立分组数量；
- 允许的提供方类型；
- 时效要求；
- 可接受的可复现性与校准状态；
- 冲突策略；
- 可用输出；
- 阻断输出和行动；
- 可信保证不足时的下一步动作。

v0.1按照有类型结果的精确值进行比较，不取平均、不推断来源优先级、不应用未声明的多数表决，也不静默删除少数结果。

可信保证评估成功后，可以把档案声明的一个输出标记为可用，但不会发布该输出、授权行动或执行行动。被档案阻断的行动即使可信保证成功也继续阻断。

## 命令行

```bash
geotask provider inspect --profile --format json
geotask provider inspect provider-descriptor.json
geotask provider check provider-descriptor.json verification-request.json
geotask provider validate verification-response.json \
  --request verification-request.json \
  --descriptor provider-descriptor.json
```

所有命令均为只读操作，不提交请求、不获取外部证据、不调用网络服务、不发布生产结果、不授权行动，也不执行副作用。

## GT29参考案例

GT29使用完全虚构的数据：

- 模拟权威气象服务：8米/秒；
- 模拟现场传感器：13米/秒；
- 任务风速上限：12米/秒。

两个响应都处于有效期内，也来自两个不同的独立性分组，但数值彼此冲突。因此天气结论保持未知，天气核验输出、自动起飞授权和起飞指令继续阻断，下一步是请求第三个独立气象验证来源。

## GT30参考案例

GT30加入第三个虚构独立来源：移动测风激光雷达同样给出13米/秒。三个响应全部新鲜、可复现、满足校准要求，并来自三个独立分组，但整体仍包含8米/秒和13米/秒两个不同数值。

可信保证档案v0.1没有声明多数表决，也不会静默删除少数来源。因此二比一不能自动升级为已核验，结果继续保持未知，下一步改为请求显式气象裁决。

## GT31参考案例

GT31在GT30冲突之后加入一个虚构人工复核提供方。验证请求绑定三份原始响应、GT30可信保证档案与评估，以及一份虚构上下文证据。人工复核保留全部三份响应，并说明两份13米/秒读数是有效的局部测试气流观测，但不适用于当前任务走廊环境风速命题。

人工响应仍不能自行声明独立核验完成或获得行动权限。独立可信保证评估把当前命题的天气核验结论标记为可用；既有起飞控制评估继续独立阻断自动起飞授权和起飞指令，因为空域、运营人、起降场、气象放行和任务授权仍缺失。因此天气结论可用不等于生产发布、现实授权、指令发送或行动执行。

## 公开边界

公共规范只包含接口、严格校验、离线参考逻辑和虚构案例。生产连接器、凭据、来源质量评分、跨来源治理、行业规则、客户流程、生产结果发布和行动执行均不属于GeoTask核心。
