仓储机器人 · 单容量时空资源协调

两台机器人都要通过同一条窄通道，谁应该先走？

机器人A执行紧急出库，机器人B为空载返程。两条路线都进入容量为1的单向窄通道，占用时间也发生重叠。

selected_action = robot_b_wait

路线重叠、时间重叠、通道容量不足

机器人 A

紧急出库
优先级 90

通道窗口：08:30–08:35

机器人 B

空载返程
优先级 40

通道窗口：08:32–08:37

两条路线都经过单向窄通道，时间窗口08:32–08:35发生重叠，而通道容量只有1。

显式规则把冲突转换成协同动作

coordinate-narrow-aisle-c1

先行机器人robot_a
等待机器人robot_b
等待时长4 minutes
新通道窗口08:36–08:41

动作：B 等待至 08:36，在安全等待点保持静止。

B提前进入
同时进入通道

恢复条件：robot_a_cleared_corridor == true and current_time >= 08:36

第一步：让模型选择协同动作

模型可选择让A等待、让B等待或重新规划B的路线。本案例已经提供明确优先级、安全等待点和清空缓冲规则。

得到模型建议后返回本页，选择对应动作并验证。

查看将被复制的完整 GeoTask
geotask:
  id: "gt10-robot-corridor-coordination"
  name: "GT10 Warehouse Robot Narrow-Aisle Coordination"
  schema_version: "1.0"

application_context:
  scenario: "warehouse_robot_single_capacity_corridor"
  resource_id: "narrow_aisle_c1"
  resource_capacity: 1

known_results:
  robot_a_uses_corridor: true
  robot_b_uses_corridor: true
  corridor_occupancy_overlap: true

robot_tasks:
  robot_a:
    mission: "urgent_outbound_order"
    task_priority: 90
    original_corridor_window: ["08:30", "08:35"]
  robot_b:
    mission: "empty_return"
    task_priority: 40
    original_corridor_window: ["08:32", "08:37"]
    holding_point: [140, 0]

coordination_policy:
  priority_rule: "higher_task_priority_first"
  tie_breaker: "request_dispatch_review"
  clearance_buffer_minutes: 1

coordination_plan:
  selected_action: "robot_b_wait"
  proceed_robot: "robot_a"
  wait_robot: "robot_b"
  revised_entry_time: "08:36"
  revised_exit_time: "08:41"
  wait_duration_minutes: 4
  resume_when: "robot_a_cleared_corridor == true and current_time >= 08:36"
  next_action: "coordinate_passage"
  expected_status: "coordinated"

instructions_for_model:
  - "Choose one action from robot_a_wait, robot_b_wait, or replan_robot_b."
  - "Apply the explicit priority rule before proposing a more expensive route change."
  - "Preserve the holding point, clearance buffer, revised time window, and resume condition."
  - "Mark model-produced fields as model_generated."
  - "Do not claim local_deterministic verification unless a separate executor has run."

GT10的“高优先级先行”是本案例明确给定的局部规则。真实仓储系统还需考虑制动距离、载荷、通道方向、等待点容量和全局死锁。
