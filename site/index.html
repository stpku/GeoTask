Spatiotemporal Task Context Engine for AI Agents

不是给 Agent 更多上下文，
而是给它当前任务真正需要的上下文。

GeoTask 围绕任务构造相关、适用、分辨率足够且可明确判断充分性的时空上下文，并在现实变化后只重评真正受影响的部分。

Task Sufficiency at Minimum Context Cost —— 用最小必要上下文支撑任务，同时让 Critical Context Miss 保持可见。

Problem

Agent 的上下文问题，本质上不是“装多少”，而是“什么足够”。

长上下文窗口、RAG、数据库和工具都能提供更多信息，但它们不会自动回答这些信息是否真的适用于当前任务。

相关 ≠ 适用

同一条事实可以与任务主题相关，却不适用于当前对象、区域、时间窗口或运行条件。

有数据 ≠ 分辨率足够

存在地图、气象、库存或传感器值，并不意味着空间、时间、精度和语义粒度足以支持任务。

上下文很多 ≠ 上下文充分

大 payload 可能仍遗漏一个 critical requirement；反过来，大量可选信息也可能只是增加 token、网络与认知成本。

Task → Context，而不是 World → Prompt

GeoTask 先从任务建立 Requirement，再评估候选信息；Relevance、Applicability、Resolution 和 Sufficiency 保持分离，最终形成最小充分 TaskContext 与显式 Gap / Trace。

Task→Requirements→Candidates→Relevance→Applicability→Resolution→Sufficiency→Minimum TaskContext
核心对象包括 TaskFrame、ContextRequirement、ContextCandidate、ContextAssessment、ContextGap、SufficiencyAssessment、TaskContext、ContextConstructionTrace，以及 Minimum Context 与 Temporal Reassessment 相关合同。

Boundary

GeoTask 不拥有世界真值，也不替代 Agent Runtime。

GeoTask 的独立价值来自 Task-relative Context。上游负责提供现实候选信息，下游负责推理、领域判断与动作授权。

UpstreamWorld / Data Providers

WorldState、GIS、API、Sensor、Database、GSTAR 或其他 Provider 提供候选事实、来源和状态。

GeoTaskTask Context

判断当前任务需要什么，哪些候选相关、适用、分辨率足够，以及上下文是否充分。

DownstreamAgent / Domain System

Agent Harness 运行推理；领域系统继续拥有专业判断、授权、执行和责任边界。

Context Sufficient ≠ Domain Decision ≠ Action Authorization

Current Public Proof

已经有独立消费者，不再只靠定义证明自己。

当前公共 Core 已发布 Task Context 合同、候选 Provider、Relevance / Applicability / Resolution、Sufficiency Composition、Minimum Context 与 Temporal Continuity，并用非低空场景进行独立验证。

Warehouse Robot Picking

室内 GIS、库存 API 与通道净宽传感器分别提供 ContextCandidate。GeoTask 构造任务 Requirement，独立评估相关性、适用性与分辨率，形成 Sufficiency 和 Minimum TaskContext；传感器变化后只刷新受影响 Requirement。

Indoor GIS / Inventory API / Aisle Sensor ↓ TaskFrame → ContextRequirement[] → ContextCandidate[] ↓ Relevance / Applicability / Resolution Adequacy ↓ Sufficiency → Minimum Sufficient TaskContext ↓ Sensor Change → Bounded Temporal Reassessment

关键反例：即使通道实测宽度小于机器人宽度，只要这个测量本身相关、适用、新鲜且分辨率足够，GeoTask 仍可判断“上下文充分”；但它不会判断“机器人可以通行”。

Measure

目标不是 Context Reduction 本身，而是“充分前提下的最小成本”。

任何“减少上下文”的正指标都必须配一个反指标，避免系统通过漏掉关键事实来获得更漂亮的成本数字。

Critical Requirement Coverage ↑Counter: Critical Context Miss Rate
Sufficiency Accuracy ↑Counter: False Sufficiency Rate
Context Reduction ↑Counter: Critical Context Miss Rate
Applicability Accuracy ↑Counter: Irrelevant / Inapplicable Context Rate
Context Rebuild Locality ↑Counter: Unnecessary Context Rebuild

Research Roadmap

下一阶段研究的不是更多 GT 编号，而是 Task Context 方法本身。

GeoTask 作为独立 Foundation 持续推进自己的问题、Benchmark 和跨领域验证。

Requirement Derivation

从显式 Requirement 继续走向稳定的 Task → Requirement 方法，并保留来源与推导轨迹。

Applicability & Resolution

证明“同一事实 + 不同任务 → 不同适用性”，同时把空间、时间、精度与语义分辨率变成可评估要求。

Minimum Context Cost

在 Critical Context Miss 不上升的前提下降低 carried bytes、token、Provider latency 与恢复成本。

Temporal Reassessment

现实变化映射到受影响 Requirement，只做有界重评和必要的最小重建。

Independent Consumers

继续用第二、第三领域验证公共 Core，不让任何单一产品的数据模型塑形 GeoTask。

Open Method & Protocol

长期公共资产是 Task Context Method、Engine、Benchmark 与开放合同，而不是一个封闭领域平台。

关于旧定位：GeoTask 早期公开版本中的 Verifiable World Model / World-State Cycle / Verification 资产继续保留并维护，用于兼容与历史可追溯；它们不再定义长期语义所有权。当前定位以 Task Context Engine 为准。
